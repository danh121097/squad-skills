# Worker sessions

Read before selecting a mode or dispatching. Explicit single-session or no-delegation instructions win.
Otherwise apply the entrypoint's main/coordinator preference; use the lowest-overhead suitable mode when
no preference applies. Confirm creation, result read-back and follow-ups from live tools.

If squads-team leads, return diagnosis and ownership there; it dispatches, preserving one lead.
For build chats read [thread-handoff.md](thread-handoff.md). For subagent or peer-team dispatch read
[worker models](worker-models.md) for the selected runtime; pass proven cause, acceptance, ownership,
base, artifact path, tier and required evidence. Main owns diagnosis, routing, decisions and integration. Workers load their own skill and matched
references; main reads worker instructions only for a contract or review need.

A valid user-started launcher keeps build work pending. Missing authorization also stays pending; ask
only for the missing permission. When neither direct creation nor a valid launcher supports read-back
and follow-ups, explain the limitation and fall back to subagents, then single-session work.

Gate execution follows the effective execution mode, not the main label. Light work closes on its
combined verify pass. In single-session fallback, run required unassigned QA and Review as distinct
logical passes, disclose reduced independence and follow the entrypoint's solo/tier rules. Explicitly
independent or externally assigned gates remain pending without their required evidence. In thread mode,
required paired gates stay pending if either subagent cannot start; do not silently replace them inline.
